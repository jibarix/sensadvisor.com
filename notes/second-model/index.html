nouez: Claude Code Asks Codex for a Second Opinion

An open-source MCP server that lets Claude Code consult a read-only Codex or Gemini session, and open Claude Code sessions on my computer from my phone.

J. A. Arroyo · SENS ADVISOR

When I need a second reader

Some steps in my work are hard to undo: a production release, deleting files, a paid experiment, publishing a note, or treating an analysis as a conclusion. Before each of them I want a second reading from a model trained by another company, which can catch what the model that did the work missed.

Without a bridge, getting that reading meant two terminals and copying questions and answers between them by hand. The first version of nouez, in October 2026, removed that step with a small MCP server: Claude Code could start a read-only Codex session, send it a question and read the reply, with no terminal to manage. It has grown with my use of it. It now also reaches Gemini models, lets Claude choose a consultant’s model for each question from my usage and published scores, and lets me open or resume a project on my computer from my phone; since version 0.23.0, a dispatcher it keeps running there means I no longer have to leave a session open for that.

How I use it

Claude Code does the work and owns it. When a step needs review, Claude starts a “consultant”, a Codex or Gemini session, in the same project, sends it the relevant files and a narrow question, and keeps working while the consultant reads. The consultant’s local file access is read-only, and Claude applies any edit it proposes, so one author stays responsible for the result. nouez’s status screen lists the Codex and Gemini consultants it started across my projects, and I can select one to follow its latest turn as it runs. The reply wakes Claude when it arrives, and I treat the consultant’s findings as claims to check against their sources, in the same way as the draft’s.

My consultations fall into these groups, roughly largest first:

  • following up on earlier consultations, often to re-check fixes;
  • validating data, analyses and decisions;
  • critiquing plans and launch gates;
  • reviewing text and checking its claims;
  • researching against outside sources;
  • reviewing code or diagnosing bugs.

Many of them ask for a verdict in a fixed format, such as go, changes or no-go, followed by what the consultant did not check, so that silence is not mistaken for approval.

The phone reaches the computer through the dispatcher, a Remote Control server that nouez runs in a folder of its own, starts at each sign-in and starts again if it ends. The phone is where I work; the computer is the server. From my phone, I ask the dispatcher to open a new Claude Code session for a project, either a new folder or an existing one, and it appears in the app’s session list a few seconds later. An earlier conversation in that project can be picked up again, and a session that is stuck can be listed and closed from the phone too. For an existing folder I haven’t trusted yet, nouez opens nothing at first and returns a report of what the folder’s settings would run, such as hooks and MCP servers. Claude asks me whether to trust it; if I agree, Claude requests trust, and nouez records it only if the reported files are unchanged. A session can also list my projects, so the dispatcher reaches all of them.

What nouez is, and why MCP

nouez is a small MCP server written in Python using only the standard library, so it needs no packages. Claude Code talks to it over the Model Context Protocol. For Codex consultations, it talks to the Codex app-server daemon on the same computer, where the consultant sessions live and keep their whole conversation until they are stopped.

Since version 0.15.0, a consultant can also run on Google’s Antigravity CLI, for second opinions from Gemini models on Google’s quota. Those consultants are read-only through Antigravity’s deny rules: they read files but run no commands, so Claude puts any diff or output they need into the message, and they take one message at a time. I chose MCP so that Claude Code can call the bridge as named tools, with a permission rule for each tool and one user-level setup across projects, including sessions opened from the phone. The server’s instructions tell Claude when to use each tool, and the Python code fixes the consultant’s sandbox settings instead of leaving Claude to write the command. A fixed script could enforce the same settings, and a personal skill could also be available in every project, but neither gives Claude a set of named tools with their own permissions.

My harness and models

Claude Code is my main harness, running Claude Opus 5.5. My Codex configuration still starts consultants on gpt-6.1-sol at high reasoning effort, but Claude now sets the model and effort for each question, following my consult skill: reviews usually go to gpt-6.2-astra at high, claims I’ll rely on go to Astra, re-checks of applied fixes to gpt-6.2-sol at medium, and plan critiques to Gemini 4 Neon at its highest effort. The skill bases those choices on two published sources: Artificial Analysis, for its Intelligence Index and its scores by subject and task, and BullshitBench, which measures how often a model says so when a question rests on a false premise, the reason plan critiques go to Neon. A change keeps the consultant’s context, and Claude sets the usual values again once the hard question is done. I find the pairing works well, because the models are trained by different companies and read the same files differently.

What it sends, and what it can’t do

nouez sends no telemetry and has no hosted service: nothing about me or how I use it goes to its author. The bridge is one Python file using only the standard library, and its own web requests go to just two places: GitHub, to check for the latest release, and Artificial Analysis, for model scores, only when I set a key. Everything else goes through the CLIs I installed, so my messages reach OpenAI, Google or Anthropic as they would without nouez.

The phone dispatcher uses Claude Code’s own Remote Control, which connects out to Anthropic. The dispatcher opens no inbound port, and I use the Claude app and the claude.ai account I already have. The consultants nouez starts have read-only file access: Codex runs in a read-only sandbox with approvals set to never, and Antigravity’s rules deny file writes and edits, commands, MCP tools and URL actions. An Antigravity consultant can still search and read web pages, and nouez asks it not to schedule work, but Antigravity has no rule to enforce that. nouez itself never opens a credentials file; it only checks when Claude Code’s has changed. A check in the repository, verify.py static, looks in the source for changes to the allowed web destinations, credential-file access and consultant permissions, and CI runs it too. It can catch a plain regression, not every way around them.

Try it

The code, with setup instructions, the tested versions and a security policy, is at github.com/jibarix/nouez under the MIT licence. It needs Claude Code and Python; consultations also need the Codex CLI, Google’s Antigravity CLI or both, while the session tools for the phone work without either. Its doctor command checks the setup, the dispatcher included. Its automated checks and unit tests run on Windows, macOS and Linux; I use it day to day on Windows 11.

Before you enable it, know its limits. Agreement between two models does not establish truth, since both can share a gap in their knowledge. A consultant can read anything its sandbox permits, typically including files outside its project. Any Claude Code session with the server enabled can message any Codex session on the computer, and sessions I opened myself keep their own permissions and may be able to write. Any such session can also close any other Claude Code session under my account, and trusting a folder from the phone lets its hooks and MCP servers run. The dispatcher gives my phone these session tools whenever the computer is awake, I’m signed in and Remote Control is connected; renewing my Claude Code sign-in still needs the computer, and anyone signed in to my claude.ai account can start a session in the dispatcher folder. nouez works on one machine only, and it depends on an experimental Codex protocol and an Antigravity mode not documented as stable, either of which can change between releases, which is why the repository records the last combination of versions known to work.

Method and limits

The description of nouez follows its README, changelog, security policy and code at version 0.23.0; the note was first published on 20 November 2026 at version 0.12.3 and updated on 24 November. The kinds of consultation come from the messages Claude Code sent to consultants on my laptop, sorted by an agent with keyword rules and checked by hand on a sample; about one label in ten was wrong, so the order of the kinds is approximate.
